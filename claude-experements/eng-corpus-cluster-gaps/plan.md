# CLAUDE.md — План экспериментов по обнаружению семантических пробелов

## Контекст проекта

### Данные
Английский корпус, включающий исторические тексты (Early Modern English — 16–17 вв.). Уже построены эмбеддинги: TF-IDF → truncated SVD с σ^0.5, словарь ~70k лемм, d=100–300. Постобработка: center (вычитание среднего вектора) + L2-normalize (все векторы на единичной сфере). Без центрирования Вишарт видит один гигантский кластер (уже проверено). Частоты слов доступны.

Корпус содержит **диахроническую смесь**: архаичная лексика ('gan', 'helpe', 'daye', 'soule', 'wight') соседствует с современной. Вишарт-кластеризация уже ловит эту структуру — архаика выделяется в отдельные кластеры.

### Что такое семантический пробел
Семантический пробел — область пространства эмбеддингов, где по окружающей структуре (соседние кластеры, аналогии из других областей) **ожидается** слово, но его нет. Примеры: у немцев есть Schadenfreude, у англичан однословного эквивалента нет; в Early Modern English было слово для концепта, которое в Modern English утрачено.

Пробелы бывают:
- **Синхронные** — концепт не лексикализован в языке вообще
- **Диахронические** — слово *было*, но утрачено (особенно актуально для нашего корпуса с архаикой)
- **Внутриязыковые** — один тематический кластер богаче другого структурно похожего

### Теоретический каркас: производная Радона-Никодима
Формализация пробела через теорию меры. Пусть ν — эмпирическая мера распределения слов в одном кластере (или языке), μ — «референсная» мера (другой кластер, другой язык, или «ожидаемое» распределение). Производная Радона-Никодима dν/dμ(x) показывает, во сколько раз ν плотнее μ в точке x:
- dν/dμ(x) ≫ 1 — избыток лексики (перенасыщенная область)
- dν/dμ(x) ≈ 1 — нормальное покрытие
- dν/dμ(x) ≈ 0 — **семантический пробел** (референс ожидает слово, но его нет)

### Почему RuLSIF, а не прямая оценка плотностей
Наивный подход (оценить плотности p̂ и q̂ через KDE, поделить) не работает в d > 20 из-за проклятия размерности. **RuLSIF** (Relative unconstrained Least-Squares Importance Fitting) оценивает отношение плотностей **напрямую**, минуя оценку отдельных плотностей. Он моделирует α-относительное отношение r_α(x) = p(x)/(αp(x) + (1-α)q(x)), которое ограничено сверху 1/α — это обеспечивает численную устойчивость в областях малого перекрытия (именно там, где пробелы). Решение — аналитическое (одно обращение матрицы b×b, b=100–200 ядерных центров), гиперпараметры подбираются через аналитическую LOOCV.

### Зачем нужно выравнивание кластеров
Мы сравниваем два кластера из одного пространства эмбеддингов, но расположенных в **разных областях** ℝᵈ. Чтобы RuLSIF мог сравнить их плотности, нужно привести оба кластера к общей системе координат:
1. **Центрирование** — вычесть центроид каждого кластера (теперь оба вокруг нуля)
2. **Gromov-Wasserstein** — найти соответствия между точками без supervision, сравнивая *внутренние* попарные расстояния (не требует общего пространства)
3. **Прокрустово вращение** — ортогональная матрица R, совмещающая якорные пары из GW
4. **CCA-whitening** — выравнивание ковариационных структур, чтобы ширина ядра σ в RuLSIF работала одинаково в обоих облаках

### Конвейер целиком
```
Эмбеддинги → Кластеризация → Выбор пар кластеров →
→ GW (якоря) → Procrustes (вращение) → CCA-whitening →
→ PCA до d≤50 → RuLSIF → Поиск минимумов r̂_α →
→ Проекция обратно → Валидация через WordNet
```

## Фаза 1. Валидация эмбеддингов

Эмбеддинги — фундамент всего пайплайна. Если cosine similarity в пространстве эмбеддингов не коррелирует с человеческими оценками семантической близости, то кластеры будут бессмысленными, а density ratio — шумом.

Проверить качество на стандартных бенчмарках:

- **Word similarity:** SimLex-999 (чистая similarity, не relatedness — самый строгий тест), WordSim-353 (relatedness), MEN-3000, RW (Rare Words — особенно важен, т.к. корпус содержит архаику). Метрика — Spearman ρ между cosine similarity и human scores
- **Word analogy:** Google Analogy (king − man + woman ≈ queen), BATS (40 типов отношений). Метрика — accuracy@1. TF-IDF-SVD обычно слабее word2vec/GloVe на аналогиях, но syntactic relations (plurals, tenses) должны работать
- **Concept categorization:** AP (Almuhareb & Poesio), BLESS (Baroni & Lenci). K-means с K = число категорий, метрика — NMI. Проверяет, образуют ли эмбеддинги осмысленные кластеры

Сравнить собственные эмбеддинги (TF-IDF-SVD, PPMI-SVD, NMF при d ∈ {100, 200, 300}) с baselines (GloVe 6B d=300, fastText crawl-300d). Собственные будут слабее baselines — важно, чтобы разрыв не был катастрофическим.

Также полезно: проверить **согласованность** между тремя своими пространствами — для 500 слов посчитать Jaccard overlap k=10 NN. Если Jaccard < 0.10 — методы дают совершенно разные структуры, нужен ensemble или выбор одного.

**STOP-GATE:** хотя бы одна собственная модель даёт ρ ≥ 0.15 на SimLex. Если нет — SVD-подход не работает на этом корпусе, переходить на fastText как основу.

**Решение:** выбрать лучшую модель по среднему рангу на всех бенчмарках → использовать далее.

## Фаза 2. Кластеризация

Кластеры = семантические концепты. Плотные области пространства соответствуют группам семантически близких слов; разреженные зоны между ними — границы концептов. Именно внутри и между кластерами мы будем искать пробелы.

Используем **плотностные** методы кластеризации (не K-means), потому что: (a) кластеры в семантическом пространстве не сферические, (b) нужно выделять шум (слова, не входящие ни в один концепт), (c) нужна иерархия (концепты вложены: «животные» → «млекопитающие» → «кошачьи»).

Запустить три метода и сравнить:

- **HDBSCAN** (основной): сетка min_cluster_size × min_samples × cluster_selection_method. Предредукция через UMAP (n_components ∈ {10, 30, 50})
- **Wishart** (уже реализован): k ∈ {5, 10, 20}, α ∈ {1, 1.5, 2}. Сохранить полную иерархию для replay
- **DBSCAN** как baseline

Метрики: DBCV, silhouette, доля шума, число кластеров. Supervised-метрики (NMI, ARI) против WordNet supersenses.

**Bootstrap-стабильность:** 100 подвыборок 80%, max Jaccard per cluster. Кластеры с Jaccard < 0.6 исключить.

**STOP-GATE:** лучшая конфигурация даёт DBCV ≥ 0.20, доля шума < 30%.

**Решение:** выбрать метод с лучшим DBCV. Сохранить labels, densities, roles через `save_clustering_labels()`.

## Фаза 3. Выравнивание пар кластеров

Ключевая проблема: два кластера расположены в разных областях ℝᵈ, имеют разный масштаб и разную ориентацию осей. RuLSIF сравнивает плотности — для этого оба облака точек должны жить в **одном и том же** пространстве. Без выравнивания RuLSIF будет измерять не разницу в структуре, а разницу в положении.

Gromov-Wasserstein (GW) — ключевой инструмент: он сравнивает **внутренние** попарные расстояния (d(a₁,a₂) внутри кластера A vs d(b₁,b₂) внутри кластера B), не требуя общего пространства. Оптимальная связка γ* из GW даёт мягкое соответствие между точками. Top пары из γ* — якоря для Прокрустова вращения.

Procrustes — ортогональная матрица R, минимизирующая ‖X_anchors · R − Y_anchors‖. Ортогональность гарантирует сохранение расстояний (|det R| = 1), что критично для RuLSIF: без искажения плотностей якобианом.

CCA-whitening выравнивает ковариационные структуры: после whitening оба облака имеют единичную ковариацию → единая ширина ядра σ в RuLSIF работает одинаково везде.

### 3.1. Выбор пар

Отобрать пары кластеров для сравнения по трём стратегиям:
- (a) тематически близкие — один WordNet supersense
- (b) диахронические — архаичный vs современный
- (c) контрастные — далёкие по центроидам (null baseline)

Фильтр: ≥ 50 слов в каждом кластере.

### 3.2. Выравнивание

Последовательно:
1. **PCA** до d' ∈ {30, 50} на объединении двух кластеров
2. **Gromov-Wasserstein** (`ot.gromov.entropic_gromov_wasserstein`) → извлечь якорные пары через mutual-argmax из плана T
3. **Ортогональный Procrustes** (`scipy.linalg.orthogonal_procrustes`) на якорях
4. **Iterative refinement** (3–5 итераций: CSLS mutual-NN → Procrustes)
5. **ZCA-whitening** (опционально, если residual > 0.15)

Метрики: Procrustes residual, доля mutual-NN якорей, MMD² до/после.

**STOP-GATE:** доля mutual-NN якорей ≥ 30% для тематически близких пар. Для контрастных (c) должна быть < 15% (sanity check).

## Фаза 4. RuLSIF

RuLSIF моделирует отношение плотностей как линейную комбинацию гауссовских ядер: r̂_α(x) = Σⱼ θⱼ · K(x, cⱼ), где cⱼ — ядерные центры (подмножество точек из данных, обычно b=200), а θⱼ — веса, найденные аналитически. Функция r̂_α(x) определена в любой точке пространства, не только в точках данных.

Параметр α контролирует компромисс: α → 0 даёт обычное p/q (точно, но нестабильно), α → 1 даёт тривиальное отношение ≈ 1 (стабильно, но бесполезно). Типичный выбор α = 0.1.

**Критически важно**: RuLSIF с гауссовским ядром деградирует при d > 50. Обязательно применять PCA-редукцию перед RuLSIF. Эффективная внутренняя размерность эмбеддингов обычно 10–20, поэтому d' = 30–50 после PCA — разумный выбор.

### 4.1. Синтетический тест (обязательно первым!)

Взять один кластер, удалить из него 20–50% точек в компактной области → это искусственный «пробел». Запустить RuLSIF на (полный кластер, кластер с дыркой). r̂_α должен падать в области удалённых точек.

Метрика: AUC обнаружения удалённых точек. **Если AUC < 0.70 — метод не работает при данных параметрах, варьировать α и d'.**

### 4.2. Подбор гиперпараметров

- `alpha ∈ {0.05, 0.1, 0.3, 0.5}` — RuLSIF α
- `kernel_num ∈ {100, 200}` — число ядерных центров
- `d' ∈ {10, 30, 50}` — размерность после PCA (критично! При d > 50 RuLSIF деградирует)

Библиотека: `densratio` (pip install densratio). σ и λ подбираются автоматически через LOO-CV.

Выбор: максимальный α-PE на значимых парах при α-PE ≈ 0 на permutation-null (перемешать метки p/q).

### 4.3. Запуск на реальных парах

Для каждой пары из Фазы 3: выровненные облака → RuLSIF → массив r̂_α для каждого слова.

## Фаза 5. Поиск и валидация пробелов

После RuLSIF у каждого слова есть число r̂_α. Высокое значение (≈ 1/α) — кластер-источник (P) плотнее кластера-цели (Q) в этой области: у P есть слова, которых в Q нет. Низкое значение (≈ 0) — наоборот. Пробелы в Q — это точки из P с высоким r̂_α.

Важно: не все минимумы r̂_α — настоящие пробелы. Многие — просто разреженные области (редкие слова), шум или морфологические варианты. Поэтому нужна многоуровневая валидация.

### 5.1. Поиск кандидатов

Три метода, агрегировать голосованием (≥ 2 из 3):
- **k-NN локальные минимумы:** r̂_α(x) ≤ r̂_α(u) для всех k=15 соседей, фильтр < quantile(0.05)
- **Уровневые множества:** связные компоненты {x : r̂_α(x) < ε} в k-NN графе
- **Persistent homology** (gudhi): 0-persistent bars длиной > 10% range

Для каждого кандидата: проекция обратно в исходное пространство (обратить PCA + Procrustes + centering), найти 20 ближайших реальных слов.

### 5.2. Валидация

- **WordNet:** для каждого кандидата проверить — есть ли соответствующий synset в кластере-акцепторе. Отсутствие = indicator пробела
- **Диахроническая:** для пар архаичный/современный — проверить через WordNet obsolete/archaic маркеры
- **Permutation test:** перемешать метки p/q, пересчитать r̂_α → кандидат валиден если в нижних 1% хвоста

**STOP-GATE:** ≥ 30% кандидатов подтверждены хотя бы одним методом валидации.

## Три главных риска и что делать

1. **Проклятие размерности в RuLSIF** — гауссовское ядро K(x,c) = exp(-‖x-c‖²/2σ²) при d > 50 становится почти постоянным (все расстояния концентрируются вокруг одного значения). **Mitigation:** обязательно PCA до d ≤ 50 перед RuLSIF. Если AUC на синтетике < 0.70 при d=50, снижать до d=30 или d=10.

2. **Разреженная область ≠ лексический пробел** — область может быть пустой просто потому, что корпус мал (70k слов — не весь язык), а не потому, что концепт отсутствует. **Mitigation:** валидировать каждый кандидат через WordNet (есть ли synset без lemma в кластере-акцепторе) + permutation test (значим ли этот минимум статистически).

3. **Диахроническая смесь** — корпус содержит Early Modern English. Архаичное слово, вытесненное современным синонимом, — это не пробел, а замена. **Mitigation:** при сравнении архаичный/современный кластер проверять через WordNet: если у «пробела» в современном кластере есть synonym в том же кластере, это замена, а не потеря. Настоящая потеря — когда весь synset отсутствует.
